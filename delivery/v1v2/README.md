# v1 / v2 delivery drivers

These are the per-clip drivers that produced the v1 and v2 HaWoR deliveries, before
`delivery/run_v3_clip.sh` folded the whole pipeline into one script. They are kept because
they record how the earlier runs were actually produced — the comparisons in
`out/*/eval_v1_vs_v2/` were generated by these and cannot be reproduced from the v3 script.

- `run_one_clip.sh`  — the full v1 pipeline: fetch -> inference -> QC -> **gate** -> render -> score -> upload -> reclaim.
  The gate is the important part: it asserts reprojection median < 1.0 px and world->cam
  roundtrip < 1e-4 m, and exits non-zero *before* the upload block. A clip that fails is
  therefore computed but never published.
- `run_queue.sh`     — runs the remaining clips one at a time, recording pass/fail per clip in
  `out/queue_status.txt` and carrying on past a failed gate instead of abandoning the queue.
- `deliver_clip.sh`  — render + score (+ optional upload) for a clip whose inference already ran.
- `run_v2.sh`        — the one-off episode_048 v2 run (`HAWOR_TRACK_FIX=1`), kept as the first
  before/after of the track-id handedness fix.
- `run_v2_clip.sh`   — the generalised v2 driver; upload is a separate step so it can be retried
  after an SSO re-login without redoing the compute.

Both note that they deliberately do not use `set -u`: the `egoforce` env's
`activate.d/activate-gcc_linux-64.sh` dereferences an unset `SYS_SYSROOT` and would abort.
These scripts run inference in the `hawor` env and render/score in the `egoforce` env,
activating the latter but never installing into it.
